# エフェクト試作の結果

引継ぎ資料 エフェクト試作の結果。

## 結論

- **方針を変えた**。Unityのエフェクトを再生して全粒子を毎フレーム記録し、エンジンで再生する方式(以下「記録方式」)を試作した。手作業で組み直す案Aと、連番テクスチャに焼く案Bは試していない
  - 理由: Aは調整の手作業が多い。Bは回り込んだときに平たく見える
- Particle Packの`SmallExplosion`で、元と記録の再生が見分けにくい程度に一致した
- 計画とデータ形式: `docs/design/plans/effect-recorder.md`。ツール: `C:\Git\EffectRecorder`(GitHub private)

## タスク2: 記録方式の結果

| 観点 | 結果 |
|---|---|
| 見た目 | 元と記録を左右に並べ、左右の画素の差は平均1/255以下(全フレーム)。`effect-recorder-frame010.png` / `effect-recorder-frame045.png` |
| 作業時間 | 1エフェクトあたり、ボタン1つで数秒。手作業なし |
| データの大きさ | `SmallExplosion`(178フレーム、最大66粒)でbin 355KB + テクスチャ |
| Xboxでの描画コスト | 未計測 |

試作で分かった、再生側(D3D12)で必要なこと:

- **描画順**: エミッターはJSONの並び順で描く。距離で並べ替えると前後が入れ替わって点滅する
- **Flipbook Blending**: 連番の今のコマと次のコマを、記録した混ぜ具合で混ぜる。Particle Packの爆発と煙で使われている
- **伸ばす板(Stretched)**: 粒子の位置を先端にして、速度の逆向きに尾を引く
- **回転**: Unityの回転は時計回りが正
- **ソフトパーティクル**: 深度テクスチャが要る(地面との境目をぼかす)。Particle Packの多くの材質で有効
- **ライティング**: URPのParticles Litの材質は、板の法線とライティングの計算が要る

## 設計への要望

- エフェクトの再生の窓口(EffectSystem)は、記録方式の再生を中身として差し替えられること
- 骨への追従、色・大きさの実行時変更は、記録方式では「再生位置・向きの変更」と「全体の色・大きさの倍率」として扱う(記録の中身は変えない)

## やっていないこと

- 歪み(Shockwaveの`_DISTORTION_ON`)の再現。確認用の再生では元の材質をそのまま使っているので、Unity上では出ているが、D3D12では別途実装が要る
- ループするエフェクトのつなぎ目、乱数違いの複数パターン
