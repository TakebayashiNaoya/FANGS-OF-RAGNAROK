# 入力のアクション化の要件

既存の入力設計(`README.md` 7 節、`ClassDiagram.drawio` の 8・9 ページ)を、アクション基準に変える。

## 背景

- 今の設計:エンジンは Xbox のパッド配置を基準にした仮想パッド(`ControlState`)を作る。キーボードとマウスは JSON でパッドのボタンに割り当てる(`"A": "F"`)。ゲームのコードは `IsTapped(PadButton::B)` のようにボタンで書く
- 先生のレビュー:Unity の Input System のように「ジャンプ = A」のようなアクション基準にし、プレイヤーが割り当てを変えられるとよい。DualSense にも対応できるとよい

## ユーザーが決めたこと

- アクション基準にする(ゲームのコードはアクションで書く)
- **キーの割り当てを変える画面**を今回の設計に含める
- **PC 版と Xbox 版**を出す。PC 版では DualSense を使えるようにする
- ボタンの名前は位置の名前(South / East / West / North)。画面に出す表示(A なのか × なのか)は機種ごとに分ける(Unity・SDL3 と同じ考え方)

## 前提(仮に決めたもの)

- 割り当てが他のアクションと重なったら、入れ替える
- PC 版のパッドの読み取りは SDL3。Xbox 版は既存どおり Windows.Gaming.Input

## 変えないもの

- CharacterCommand から先(Character・AI Controller)
- 短押し・長押し・先行入力の判定の考え方、入力は 1 フレームの最初に Main で確定する、ローカルマルチは LocalPlayer ごと

## 成功条件

- ゲームのコードにボタン名が出てこない(アクション名だけ)
- プレイヤーが画面でパッドとキーボードの割り当てを変えられ、次に起動しても残る
- PC 版で Xbox のパッドと DualSense の両方が使え、画面のボタン表示が使っている機種に合う

## 設計の方針

- 設計に書くのは後から変えにくいもの(API の境界、データ形式、スレッド、既存設計との矛盾)だけ。端のケースは実装中に直す

## やらないこと

- DualSense 固有の機能(アダプティブトリガー、タッチパッド、ジャイロ)
- Xbox 版での DualSense(本体が対応していない)
- Steam Input
