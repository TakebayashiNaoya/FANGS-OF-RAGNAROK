# 入力のアクション化の要件

既存の入力設計(`README.md` 7節、`ClassDiagram.drawio`の8・9ページ)を、アクション基準に変える。

## 背景

- 今の設計:エンジンはXboxのパッド配置を基準にした仮想パッド(`ControlState`)を作る。キーボードとマウスはJSONでパッドのボタンに割り当てる(`"A": "F"`)。ゲームのコードは`IsTapped(PadButton::B)`のようにボタンで書く
- 先生のレビュー:UnityのInput Systemのように「ジャンプ = A」のようなアクション基準にし、プレイヤーが割り当てを変えられるとよい。DualSenseにも対応できるとよい

## ユーザーが決めたこと

- アクション基準にする(ゲームのコードはアクションで書く)
- **キーの割り当てを変える画面**を今回の設計に含める
- **PC版とXbox版**を出す。PC版ではDualSenseを使えるようにする
- ボタンの名前は位置の名前(South / East / West / North)。画面に出す表示(Aなのか × なのか)は機種ごとに分ける(Unity・SDL3と同じ考え方)

## 前提(仮に決めたもの)

- 割り当てが他のアクションと重なったら、入れ替える
- PC版のパッドの読み取りはSDL3。Xbox版は既存どおりWindows.Gaming.Input

## 変えないもの

- CharacterCommandから先(Character・AI Controller)
- 短押し・長押し・先行入力の判定の考え方、入力は1フレームの最初にMainで確定する、ローカルマルチはLocalPlayerごと

## 成功条件

- ゲームのコードにボタン名が出てこない(アクション名だけ)
- プレイヤーが画面でパッドとキーボードの割り当てを変えられ、次に起動しても残る
- PC版でXboxのパッドとDualSenseの両方が使え、画面のボタン表示が使っている機種に合う

## 設計の方針

- 設計に書くのは後から変えにくいもの(APIの境界、データ形式、スレッド、既存設計との矛盾)だけ。端のケースは実装中に直す

## やらないこと

- DualSense固有の機能(アダプティブトリガー、タッチパッド、ジャイロ)
- Xbox版でのDualSense(本体が対応していない)
- Steam Input
