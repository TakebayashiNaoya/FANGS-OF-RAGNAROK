# エフェクト記録ツールの要件

## 目的

Unity のストアのエフェクトを、調整の手作業なしで自作エンジン(C++ / D3D12、Xbox One S)に持ち込む。
Unity でエフェクトを再生し、毎フレームの全粒子の状態を記録する。エンジンは記録をそのまま再生する。

- 連番テクスチャに焼く方式は、回り込んだときに平たく見えるので主力にしない
- Prefab の設定を Effekseer に変換する方式は、対応付けが不完全で手直しが要るので採らない

## 決まっていること

| 項目 | 内容 |
|---|---|
| 記録ツール | Unity エディタ拡張。エンジンとは別の Unity プロジェクトで作る |
| エンジン側の再生処理 | 今回は作らない |
| 確認方法 | 記録を Unity 上で再生し、元のエフェクトと並べて見比べる |
| 試すエフェクト | Unity 公式の無料素材「Particle Pack」(Particle System 製)から 1 つ |
| Unity | 6000.3.9f1 |

## 成功条件

- Particle Pack のエフェクト 1 つを記録し、Unity 上の再生が元と並べて見分けにくい
- データ形式が文書になっていて、ユーザーがそれを読んで D3D12 側の再生処理を書ける

## やらないこと

- エンジン側(D3D12)の再生処理
- ループするエフェクト、Trails モジュール、VFX Graph 製のエフェクト
- 乱数違いの複数パターンの記録
- 特殊なシェーダー(歪み、ソフトパーティクル、ライティング)の再現
- Effekseer との統合

## 制約

- 設計は最低限にする。端のケースは実装中に起きてから直す
- コードは短く素朴に書く。面接でユーザーが説明できること
