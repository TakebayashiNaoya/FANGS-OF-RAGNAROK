# コーディング規約

このリポジトリの C++ のコードの書き方を決める。決まったものから足していく。
字下げ・改行コード・文字コードは `.editorconfig` が保存のたびに揃えるので、ここには理由だけ書く。
行末の空白は保存では消えないので、保存の前に Ctrl+K, Ctrl+D(ドキュメントのフォーマット)で整形する。

## ファイル

- C++ のソースは BOM 付き UTF-8・CRLF。MSVC が日本語のコメントを `/utf-8` なしで正しく読むため。
- 字下げはタブ。行末コメントの位置合わせはスペース。

## 命名

- 識別子は略さない(`previous`、`Initialize`、`position`)。略しても通じるかを毎回考えずに済むようにするため。
- 同じ役割の型は ProjectBeast の名前を借りる。
- シングルトンの取得は `GetInstance()`。
- 定数は大文字のスネークケース(`HEADER_SIZE`)。
- メンバ変数は `m_` から始める(`m_size`)。
- 名前は中身と合わせる。返り値の型を名前に書かない(`MallocMemoryPtr` ではなく `MallocMemory`)。

## 型

- メンバを外から直接読み書きしてよいデータの入れ物は `struct`、`private` なメンバを関数で守るものは `class`。
- 大きさと個数は `size_t`。
- 値で返すゲッターの返り値に `const` を付けない。意味を持つのは参照やポインタで返すときだけ。
- ポインタの判定は `nullptr` と比べて書く(`if (m_head != nullptr)`)。`if (m_head)` でも動くが、比べて書けば整数や `bool` の判定と見分けがつく。

## 置き場所

- .cpp の中だけで使う定数と型は、その .cpp の無名名前空間に置く。
- クラスの中だけで使う型は、.h のクラスの `private:` に前方宣言だけを書き、中身は .cpp で `struct Memory::Header { ... };` の形で定義する。
  中身を書き換えても、その .h を include するファイルがコンパイルし直しにならない。
- 使うものは、そのファイルで直接 include する。ほかのヘッダーがたまたま読み込んでいるものに頼らない。
  対になる .h が include しているものは、.cpp で書き直さない。

## Debug だけのコード

- 判定は `_DEBUG` で行う(`Engine.vcxproj` が Debug 構成で定義する。`DEBUG` は定義されていない)。
- 判定は1か所に集める。値が違うだけなら、名前を1つにして値だけを `#ifdef` で書き分け、使う行には `#ifdef` を書かない。
  使う行ごとに書き分けると、囲み漏れが起きる。
- `#endif` には、短いブロックでも `// _DEBUG` を付ける。ブロックは後から伸び、伸ばすときに付け足すのを忘れるため。

## クラスの形

- 途中の `public:` / `protected:` / `private:` の上は2行空ける。

## if の書き方

- 早期リターンだけは1行で書く(`if (ptr == nullptr)	return nullptr;`)。
- それ以外は中身を別の行に書き、`{` と `}` で囲む。処理を1行に並べると横に長くなって読みにくいため。
- 中身が5行までなら `{` を条件式と同じ行に置く。6行以上なら `{` も別の行に置く。

## コメント

- 関数の説明は Doxygen 形式で .h に書く(`@brief`、`@param`、`@return`)。
- メンバ変数には行末コメントを付ける。
- 文が2つ以上のコメントは「。」で改行する。
- 名詞で終わる行末コメント(`// 合計メモリサイズ`)には「。」を付けない。

## 決めていないこと

- `prev` や `pos` のような、広く通じる略語を例外にするか。
- 1行のゲッターを強制インラインにするか(`__forceinline` と Debug の `/Ob1`)。今は `inline`。フレームループができてから決める。
